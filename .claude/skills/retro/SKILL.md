# デッキの振り返りと、テンプレートへの持ち帰り

このデッキで得たものを、テンプレートの側に持ち帰る。テンプレートが育つほど、次のデッキで同じ指摘を受けなくなる。

## 手順

1. **このデッキの指摘を洗い出す**
   - 会話の中で発表者から受けた指摘・直しの指示を時系列で並べる。`_old/` の版の違いも手がかりにする。
   - `LESSONS.md` に記録済みのものと突き合わせ、漏れていて繰り返しそうなものを `/lesson` の形式で足す。
2. **教訓を整理する**
   - 「反映先：未反映」の項目を1つずつ、`CLAUDE.md` のルール・`rules/check-rules.json` のパターン・`theme.css` の部品・`tools/` のツールのどれで実現するか決めて反映する。
   - 似た教訓は1つにまとめ、`CLAUDE.md` が長くなりすぎないよう、言い換えで済むものは既存の行を直す。
3. **自動チェックを試す**
   - `npm run check` を、完成版の `slides.md` と `_old/` の古い版の両方にかける（`node tools/check.cjs _old/slides-v3.md` など）。
   - 古い版で指摘された問題を検出でき、完成版では誤検出が出ないことを確かめる。誤検出が出るパターンは `level: "warn"` にするか、正規表現を絞る。
4. **このデッキ専用のものと、使い回せるものを分ける**
   - デッキ専用のツールや部品（特定のサイトに合わせた撮影スクリプトなど）は、設定で動く汎用の形にできるならテンプレートに持ち帰る。できないものは持ち帰らない。
5. **テンプレートに PR を出す**（発表者に確認してから）
   - 元のテンプレートは `package.json` の `slideTemplate.repo`（例: `Kenta-Matsuda/slide-template`）。
   - 作業用の一時ディレクトリに clone し、ブランチを切って、`LESSONS.md`・`CLAUDE.md`・`rules/`・`theme.css`・`tools/`・`README.md`・見本の `slides.md` の変更を入れる。デッキの中身（発表の本文や画像）は入れない。
   - テンプレートの見本で `npm run check`・`npm run images`・`npm run build` が通ることを確かめる。
   - PR の本文には、どの指摘からどのルールができたか（教訓の ID）を書く。
6. **報告する**：足した教訓の ID、変えたルール、PR の URL を伝える。
